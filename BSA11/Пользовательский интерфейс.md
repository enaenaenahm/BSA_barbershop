# БСА11_Проектирование пользовательского взаимодействия

## 1. Форма представления данных

Удобство работы пользователя во многом зависит от того, соответствует ли приложение устройству, на котором работает, и соответствует ли устройство потребности пользователя.

### 1.1 Форм-фактор проектируемого продукта

| Тип устройства                                 | Примеры применения                                             |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------- |
| **Мобильный телефон**                 | Вызов такси, покупка билетов, онлайн-запись |
| **Стационарный компьютер**       | Графические редакторы, системы управления  |
| **Ноутбук/планшет**                     | Выезд к клиенту, работа в полевых условиях   |
| **Киоск в общественном месте** | Самообслуживание, запись без персонала        |

### 1.2 Параметры для описания

| Параметр                                        | Описание                                                                                                           |
| ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **Тип приложения**                   | Маркетплейс, корпоративная система, узкопрофессиональная система |
| **Способ управления**             | Клавиатура, мышь, сенсорный экран, голосовой вызов                               |
| **Локализация**                        | Географические, языковые, часовые пояса                                                  |
| **Специальные возможности** | Для пользователей с ограничениями (зрение, слух и др.)                          |

## 2. Роли и ключевые сценарии

**Сценарий** — наглядное схематическое представление того, как пользователь решает свою задачу с помощью системы.

**Ключевой сценарий** — взаимодействие пользователя в определенной роли с системой в рамках своих целевых задач.

| Роль         | Ключевой сценарий     | Обеспечивающие сценарии                                      |
| ---------------- | ------------------------------------- | ---------------------------------------------------------------------------------- |
| Клиент     | Бронирование услуги | Регистрация, авторизация                                     |
| Менеджер | Управление записями | Просмотр отчетов, редактирование расписания |
| Мастер     | Просмотр расписания | Просмотр отзывов, отметка выполнения               |

## 3. Экранные формы

### 3.1 Структура экранных форм

Экран обычно делится на отдельные области — **фреймы**:

| Фрейм                                    | Назначение                                                                                                |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **Список**                        | Перечень экземпляров сущности с идентифицирующими атрибутами |
| **Карточка**                    | Полные атрибуты одного экземпляра                                                     |
| **Связанные сущности** | Список или карточка связанных объектов                                            |
| **Навигация**                  | Переходы между связанными объектами                                                 |

### 3.2 Вспомогательные операции

| Операция               | Описание                                                                                                                |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| **Поиск**           | Поля поиска, точность совпадения (четкий/нечеткий), минимальная длина |
| **Фильтрация** | Поля фильтрации, сохранение в сессии                                                             |
| **Сортировка** | Поля сортировки, направление (по возрастанию/убыванию)                            |

### 3.3 Принципы разработки

- Если две или более роли пользуются одними и теми же данными, экраны должны быть приближены по визуализации
- Это упрощает переход пользователя между ролями
- Инструменты для создания макетов: Balsamiq, Figma, карандаш и бумага
