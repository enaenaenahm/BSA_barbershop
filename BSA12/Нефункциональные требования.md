# БСА12_Нефункциональные требования NFR

## 1. Что такое нефункциональные требования?

**Нефункциональные требования (НФТ)** — это требования, описывающие свойства, характеристики и ограничения системы, определяющие, *как* система должна работать, а не *что* она должна делать.

### 1.1 Отличие от функциональных требований

| Функциональные требования                                                               | Нефункциональные требования                                                                                                       |
| --------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Описывают*что* система делает                                                        | Описывают*как* система работает                                                                                                |
| Поведение системы в определенных условиях                                  | Свойства и ограничения системы                                                                                                   |
| Пример: "Система должна формировать список свободных слотов" | Пример: "Система должна формировать список свободных слотов не более чем за 10 секунд" |

### 1.2 От чего зависит успешность выполнения операций?

- Количество одновременно работающих пользователей
- Техническое оборудование
- Мощность и устойчивость сетей
- Качество кода и архитектура системы
- Системное программное обеспечение

### 1.3 Классификация НФТ

| Категория         | Время выполнения (runtime)                                                                                                                                                   | Время разработки (design time)                                                                                                                          |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Атрибуты** | Доступность, Надежность, Масштабируемость, Производительность, Безопасность, Удобство использования | Расширяемость, Портируемость, Совместимость, Обслуживаемость, Локализация, Тестируемость |
| **Другие**     | Долговечность                                                                                                                                                                  | Повторяемость, Ограничения                                                                                                                     |

## 2. Выявление нефункциональных требований

### 2.1 Источники НФТ

| Источник                            | Описание                                                                                          |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **Бизнес-цели**             | Требования к масштабируемости, доступности                          |
| **Пользователи**          | Требования к удобству использования, производительности |
| **Регуляторы**              | Требования к безопасности, хранению данных                           |
| **Техническая среда** | Требования к совместимости, интеграции                                  |
| **Ограничения**            | Бюджетные, временные, технологические                                    |

### 2.2 Ключевые атрибуты качества

| Атрибут                                        | Описание                                                       | Пример                                                                    |
| ----------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| **Производительность**        | Время отклика, пропускная способность | "Время ответа не более 3 секунд"                        |
| **Доступность**                      | Время работы системы, простои                 | "Доступность 99.5% времени"                                   |
| **Надежность**                        | Устойчивость к сбоям, целостность         | "Восстановление не более 30 минут"                    |
| **Масштабируемость**            | Способность расти                                      | "Поддержка 1000 одновременных пользователей" |
| **Безопасность**                    | Защита данных, аутентификация                | "MFA для сотрудников"                                             |
| **Долговечность**                  | Срок хранения данных                                 | "Хранение данных 5 лет"                                        |
| **Удобство использования** | Интерфейс, интуитивность                         | "Современные тренды дизайна"                            |
| **Совместимость**                  | Взаимодействие с другими системами      | "Поддержка браузеров Chrome, Safari, Firefox"                 |
| **Локализация**                      | Адаптация под регион                                 | "Региональное время, форматы дат"                    |

## 5.  Выбор НФТ для задач

### 5.1 Для задачи 1 (Сеть барбершопов)

| Приоритет | Тип НФТ                                                                    | Обоснование                                                                                                                                                                                                                                          |
| ------------------ | -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1                  | **Производительность**                                   | Интерфейс для клиентов. Если веб-страница будет долго грузиться, клиент может потерять интерес к записи. Критично в сезоны высокого спроса. |
| 2                  | **Доступность**                                                 | Клиент видит свободные слоты и может записаться в любое время днем и ночью.                                                                                                                       |
| 3                  | **Масштабируемость**                                       | Архитектура должна выдерживать рост нагрузки без переписывания кода при расширении сети франшиз.                                                                            |
| 4                  | **Удобство использования + Безопасность** | Интуитивный выбор мастера и времени. Разграничение ролей доступа (мастер, бухгалтер, админ). Защита данных при оплате.                                         |
| 5                  | **Надежность + Долговечность**                      | Система не должна допускать двойное бронирование. Хранение данных клиентов для системы лояльности в течение нескольких лет.                           |

### 5.2 Для задачи 2 (Стартап доставки заказов)

| Приоритет | Тип НФТ                                                                    | Обоснование                                                                                                                                                                                                                            |
| ------------------ | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1                  | **Надежность**                                                   | Система не должна терять статусы заказов. Важнейшее требование для стартапа — клиент должен отслеживать состояние заказа.                 |
| 2                  | **Производительность**                                   | Система мгновенно должна обновлять статусы бронирования заказов.                                                                                                                         |
| 3                  | **Доступность**                                                 | Курьеры в моменте видят доступные заказы, диспетчер видит свободных курьеров.                                                                                                   |
| 4                  | **Совместимость + Масштабируемость**          | Передача данных в бухгалтерию и получение данных об оплате курьеров. Готовность к расширению сети и увеличению количества заказов. |
| 5                  | **Безопасность + Удобство использования** | Защита данных об оплате. Понятный интерфейс для курьеров и клиентов.                                                                                                                     |

## 7.  Атрибуты доступности и надежности

### 7.1 Для задачи 1 (Барбершоп)

**Атрибуты доступности**

| Атрибут                                  | Значение                                                                           | Обоснование                                                                                                                                                          |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Время доступности               | **99.5% времени в сутки**                                               | Клиенты могут записываться в любое время. В пиковые периоды спрос возрастает до 150%.                        |
| Плановые простои                 | Допустимы раз в месяц с 04:00 до 05:00                                | Ночью трафик записи минимален. Время для технического обслуживания.                                                   |
| Регламент восстановления | **Не более 2 часов**                                                     | Бизнес может потерять клиентов, если запись недоступна несколько часов в рабочее время.               |
| Точка восстановления         | Потеря данных не более чем за**15 минут** до сбоя | Допустимо потерять несколько записей, но не критично. Важнее сохранить целостность расписания. |

**Атрибуты надежности**

| Атрибут                          | Значение                                                               | Обоснование                                                                                                                                                        |
| --------------------------------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Целостность данных     | **Атомарность операции записи**                 | Система не должна допускать двойного бронирования одного слота.                                                        |
| Устойчивость к сбоям  | **Резервирование ключевых компонентов** | При отказе сервера БД система должна переключиться на резервный без потери последних записей. |
| Контроль целостности | **Автоматическая проверка расписания**   | Предотвращение ситуаций, когда мастеру назначено две услуги одновременно.                                     |
| Обработка ошибок         | **Информирование пользователя**                | При сбое клиент видит понятное сообщение, а не "ошибка 500".                                                                      |

## 8. Атрибуты масштабирования и локализации

### 8.1 Для задачи 1 (Барбершоп)

**Атрибуты масштабирования** — потребность **высокая**

| Требование                                             | Описание                                                                                                                                                                                                    |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Горизонтальное масштабирование      | Добавление новых серверов, а не наращивание мощности одного. Добавление новых точек не требует переписывания кода. |
| Масштабируемость базы данных           | Шардирование (распределение данных) по географическому признаку (по регионам).                                                                    |
| Эластичность                                         | Быстрое наращивание мощностей в пиковые сезоны и снижение после.                                                                                             |
| Масштабируемость админ-интерфейса | Добавление мастеров и менеджеров в разных регионах не создает сложностей.                                                                            |

**Атрибуты локализации** — потребность **средняя**

| Требование                        | Описание                                                                                                                                                  |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Временные зоны                 | Критически важно. Мастер в Калининграде и во Владивостоке работают по местному времени. |
| Форматы даты и времени   | Отображение в формате ДД.ММ.ГГГГ.                                                                                                      |
| Региональные праздники | Учет при расчете пиковых нагрузок и автоматических напоминаний.                                            |
| Валюта                                | Не требуется (единая валюта — рубль).                                                                                                |

### 8.2 Для задачи 2 (Доставка)

**Атрибуты масштабирования** — потребность **высокая**

| Требование                                                     | Описание                                                                                                                                                                                     |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Масштабирование по нагрузке                     | Рост количества заказов с сотен до десятков тысяч в день без деградации.                                                                 |
| Масштабирование мобильного приложения | Backend должен справляться с ростом курьеров с 50 до 1000+, постоянно обновляющих статусы.                                             |
| Масштабирование базы данных                     | Высоконагруженная система с частыми операциями записи требует продуманной архитектуры (NoSQL + реляционная). |
| Географическое масштабирование              | При выходе в новые города — централизованная или распределенная архитектура.                                                       |
